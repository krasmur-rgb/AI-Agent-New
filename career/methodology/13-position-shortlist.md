# 13 · Шорт-лист позиций: из профиля — в список ролей и набор резюме

JTBD: «Когда профиль готов, хочу выбрать позиции, на которые реально и выгодно
подаваться, чтобы не гадать и не писать резюме "обо всём"». Звено между
профилем (`02`) и резюме (`03`): превращает позиционирование из формулировки
в процедуру с выбором.

**Позиция ≠ вакансия.** Позиция = роль + уровень + сегмент («Senior backend
(Python) в продуктовые финтехи», «Data engineer в e-commerce»). Вакансии —
конкретные объявления, они приходят позже (`vacancy-analysis`). Шорт-лист
позиций определяет, сколько мастер-резюме мы делаем и как они называются.

## Процедура

### 1. Генерация кандидатных позиций (5–8 вариантов)

Из фактов профиля, по трём линиям:

- **Прямое продолжение** — та же роль, тот же/следующий уровень;
- **Смежные** — тот же стек/домен, другая роль (разработчик → SRE/архитектор;
  аналитик → продакт; инженер → техлид);
- **Нишевые комбинации** — редкие пересечения опыта, где конкуренция ниже,
  а профиль кандидата выглядит уникально (домен × навык × язык).

Каждый вариант — с обоснованием: какие достижения профиля дают право на эту
позицию. Вариант без опоры на профиль в список не попадает.

### 2. Проверка рынком

Для каждого перспективного варианта собрать 3–5 реальных свежих вакансий
(hh/LinkedIn/борды) и оценить:

| Критерий | Как считать |
|---|---|
| **Матч** | усреднённые must-have этих вакансий × профиль; порог жизнеспособности ≥ 60% (`01-pipeline.md`) |
| **Объём рынка** | сколько активных вакансий по позиции в целевом гео/формате; единичные вакансии = не позиция, а лотерея |
| **Вилка** | зарплатный диапазон по `09-resources.md` против ожиданий из профиля |
| **Интерес** | 1–5, спрашивается у пользователя, не угадывается |

### 3. Выбор шорт-листа: 2–4 позиции

- Меньше 2 — хрупко (одна позиция = одна точка отказа при слабом рынке);
  больше 4 — распыление: каждое резюме требует поддержки, адаптаций и своего
  словаря.
- В шорт-лист входят позиции с матчем ≥ 60%, живым рынком и интересом ≥ 3.
- Позиция-мечта с матчем 50–60% может войти дополнительной, с планом добора
  и пониманием, что конверсия будет ниже.
- Результат фиксируется в профиле (блок «Позиционирование»): список позиций,
  каждая — с обоснованием и опорными достижениями.

### 4. Мастер-резюме на каждую позицию шорт-листа

- По каждой позиции — свой цикл `resume-build` → `resume-review` до ship
  (≥ 85/100). Название резюме = поисковый запрос рекрутёра по этой позиции
  (`04-market-ru.md`).
- Все резюме собираются из ОДНОГО профиля: разные ранжирование, отбор и
  словарь — одни и те же факты. Противоречия между резюме (разные цифры
  одного достижения) — блокер.
- Одно резюме = одна позиция. «Универсальное» резюме под две позиции сразу —
  ошибка, ради которой шорт-лист и существует.
- На hh — отдельное резюме под каждую позицию (лимит площадки позволяет).

## Пересмотр шорт-листа

Шорт-лист — гипотеза, воронка её проверяет. На еженедельном разборе
(`job-search-strategy`): если по позиции 2+ недели нет вакансий или конверсия
отклик → просмотр устойчиво ниже других позиций — позиция заменяется следующим
кандидатом из списка шага 1. Решение по данным, не по настроению.
