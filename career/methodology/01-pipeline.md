# 01 · Пайплайн: от профиля до оффера

Поиск работы — это продукт с одним пользователем. У него есть дискавери (кто я и
куда иду), производство (резюме и отклики), дистрибуция (каналы) и метрики (воронка).
Методология описывает каждый этап; скиллы автоматизируют их.

## Этапы

```
ПРОФИЛЬ → ПОЗИЦИОНИРОВАНИЕ → МАСТЕР-РЕЗЮМЕ → СТРАТЕГИЯ ПОИСКА
   → [цикл по вакансиям: разбор → адаптация → отклик]
   → интервью → оффер → переговоры
```

### 1. Профиль (career-profile-intake)

Инвентаризация карьеры: весь опыт, достижения с цифрами, навыки, образование,
артефакты (проекты, публикации, код). Это сырьё. Собирается один раз, обновляется
по мере поиска (вспомнил достижение — дописал).

**Критерий готовности:** по каждому месту работы есть ≥ 2 достижений с измеримым
результатом или честная пометка «результат не измерялся».

### 2. Позиционирование: шорт-лист позиций (position-shortlist)

Ответ на вопрос «на какие позиции и для какого работодателя я кандидат №1».
Формулируется до резюме, потому что резюме — аргумент под конкретную позицию,
а не автобиография. Процедура — `13-position-shortlist.md`: из профиля
генерируются 5–8 кандидатных позиций (прямое продолжение, смежные, нишевые
комбинации), проверяются рынком (матч ≥ 60%, объём вакансий, вилки) и
согласуется **шорт-лист из 2–4 позиций**.

- Каждая позиция: роль + уровень + сегмент, с обоснованием фактами профиля;
- ключевое отличие: 2–3 факта, которые отличают от типового кандидата;
- «ищу всё» = «не подхожу никому»: больше 4 позиций — распыление.

**Критерий готовности:** шорт-лист в профиле, каждая позиция — предложение
вида «[роль] с [отличие], для [сегмент]», подтверждённое фактами.

### 3. Мастер-резюме (resume-build → resume-review)

По одному сильному мастер-резюме **на каждую позицию шорт-листа** — не под
конкретную вакансию, под позицию. Все собираются из одного профиля (разные
отбор и словарь, одни факты); каждое проходит цикл написание → ревью → правки
до ≥ 85/100 по рубрике (`07-rubric.md`). Из мастеров потом делаются адаптации.

### 4. Стратегия поиска (job-search-strategy)

Каналы, темп, воронка, метрики. Подробно — `06-job-search.md`.
Ключевое: поиск — это регулярный процесс с недельным планом, а не событие.

### 5. Цикл откликов (vacancy-analysis → resume-build → cover-letter)

По каждой интересной вакансии:

1. **Разбор** — что реально требуется (must-have vs nice-to-have), какие слова
   использует работодатель, насколько профиль матчится (скоринг);
2. **Решение** — откликаться ли: матч ≥ 70% → да; 50–70% → да, если вакансия
   очень интересна и есть сильное сопроводительное; < 50% → нет, это шум в воронке;
3. **Адаптация резюме** — переранжировать и переформулировать (НЕ выдумать) под
   язык и приоритеты вакансии;
4. **Сопроводительное** — только если оно добавляет то, чего нет в резюме.

### 6. Интервью (interview-prep)

Банк мастер-историй STAR+Reflection строится из достижений профиля один раз,
под конкретное интервью истории подбираются и репетируются; после интервью —
разбор в лог. Подробно — `10-interview-prep.md`.

### 7. Оффер и переговоры (offer-negotiation)

Вилка готовится до первых скринингов; оффер оценивается как total comp
(с риск-дисконтом equity и гео-поправкой); один раунд контр-оффера — норма.
Подробно — `11-offer-negotiation.md`. Важно с первого дня: вести лог всех
откликов — параллельные процессы в воронке являются переговорной позицией (BATNA).

## Инварианты (действуют на каждом этапе)

1. **Единый источник правды — профиль.** Любой факт в любом артефакте
   прослеживается до `career/profile/profile.md`. Обратное — тоже: узнали новое
   достижение — сначала в профиль, потом в резюме.
2. **Правда без занижения.** Не выдумывать И не скромничать. «Участвовал в
   проекте» при фактическом лидерстве — такая же ошибка, как приписанный результат.
3. **Ревью всегда отделён.** Написал — отдал на review. Автор не принимает
   собственную работу.
4. **Каждый артефакт под решение читателя.** Резюме читают 6–15 секунд при
   первичном скрининге; его задача — не «рассказать всё», а получить следующий шаг.
