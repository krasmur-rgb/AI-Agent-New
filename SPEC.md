# SPEC · «Анна Каренина» — интерактивная драма

## Техническая спецификация для сборки (GitHub Pages, статический сайт)

## 1. ЧТО СТРОИМ

Интерактивная нарративная драма по «Анне Карениной». Русскоязычная, для взрослых 25–40. Игрок ведёт Анну через 5 актов; выборы невидимо копят «тягу» к одному из 5 русел (финалов). Каждая сцена сопровождается изображением. Приложение **полностью статическое и детерминированное** — никакого рантайм-ИИ, вся логика в браузере, весь текст и картинки заморожены. Хостинг — GitHub Pages (приватный репозиторий, платный тариф).

**Ключевой принцип:** данные (текст сцен, выборы, векторы) лежат в отдельном `scenario_data.json`, движок читает их оттуда. Это позволяет редактировать сценарий, не трогая код. НЕ вшивать текст сцен в JS.

## 2. СТРУКТУРА ПРОЕКТА

```

├── index.html              # каркас страницы
├── css/
│   └── style.css           # все стили (палитра ниже)
├── js/
│   ├── engine.js           # движок: состояние, тяга, переходы, финал
│   ├── render.js           # отрисовка сцены, картинки, выборов
│   └── comments.js         # система заметок отладчика + выгрузка
├── data/
│   └── scenario_data.json  # ВСЕ сцены, выборы, векторы, финалы (дан отдельно)
├── img/
│   ├── desktop/            # широкие 3:2 — I-1.jpg, I-2.jpg, … fin-L.jpg …
│   └── mobile/             # вертикальные кропы ~4:5 — те же имена
├── .nojekyll               # пустой файл — обязателен для GitHub Pages

```

**Имена файлов картинок** — из кода сцены: точка → дефис, ·L/F → -LF. Примеры: I.1 → `I-1.jpg`; IV.2·L/F → `IV-2-LF.jpg`; финалы → `fin-L.jpg`…`fin-X.jpg`; заглушки веток → `placeholder-C.jpg`, `placeholder-R.jpg`, `placeholder-X.jpg`.

## 3. МЕХАНИКА РУСЕЛ (асимметричная инерция)

5 русел = 5 финалов: **L** любовь, **C** клетка, **R** отречение, **F** руины, **X** рельсы.

Состояние: `pull = {L:0, C:0, R:0, F:0, X:0}`, `dead = Set()` (закрытые финалы).

Каждый выбор несёт `vec` — массив `{river, amt, down}`:

- `down: true` — ход к необратимому (дёшево, липко).
- `down: false` — ход к безопасному (дорого, вязко).

**Применение вектора (важно — это ядро асимметрии):**

```js
function applyVec(vec){
  vec.forEach(v=>{
    if(v.down){
      pull[v.river] += v.amt;                        // полный вес вниз
      ['C','R'].forEach(s=>{ if(s!==v.river) pull[s] = Math.max(0, pull[s]-0.4); }); // липкость
    } else {
      pull[v.river] += v.amt * 0.4;                  // вязкий ход вверх — четверть веса
    }
  });
}
```

**Лидер русла:** максимум `pull` среди не-dead. При равенстве — русло, чаще встречавшееся в последних 3 ходах (тренд).

**Закрытие финалов:** у некоторых выборов есть `kills: ["C","R"]` — эти русла уходят в `dead` навсегда (жёсткие развилки Акта III и поворотных сцен).

**Числа `amt` и коэффициенты (0.4 липкость / 0.4 вязкость) — ЧЕРНОВЫЕ,** вынести в константы в начале `engine.js` (`STICK = 0.4`, `VISC = 0.4`), чтобы калибровать после пилота.

## 4. СТРУКТУРА АКТОВ

- **Акты I, II, III, V** — линейные, сцены идут по порядку из JSON.
- **Акт IV** — 4 ветки (L, C, R, X). Движок на входе в Акт IV смотрит `leader()` и выбирает ветку. **Русло F использует ветку L** (Италия/возвращение общая для L и F). Игрок проходит ОДНУ ветку (3 сцены).
- **Акт V** — сходится для всех. Сцена V.1 имеет 5 вариантов текста (`proseByRiver`) — показывается по руслу-лидеру. Картинка V.1 одна на всех.
- **Финал** — после последней сцены V.2 движок берёт `leader()` среди живых и показывает соответствующий финал из `finales`. **Выбора концовки нет** — она сложена накопленным.

**Развязка акта** (после каждого из Актов I–IV): всплывающее окно с текстом развязки и шкалой «силы» 1–5. Сила = функция «природы» ходов акта:

```js
const w = {open:2, force:2, omen:1, hedge:0, guard:-1};
let s = actNatures.reduce((a,n)=>a+(w[n]??0), 0);
let lvl = Math.max(1, Math.min(5, Math.round((s+5)/3)+1));
```

Тексты развязок по уровню 1–5 — в JSON (`resolutions`).

## 5. ИЗОБРАЖЕНИЯ (адаптив)

Каждая сцена показывает картинку сверху, текст под ней.

- Десктоп (ширина ≥ 768px): `img/desktop/{code}.jpg`, формат 3:2.
- Мобильный (< 768px): `img/mobile/{code}.jpg`, вертикальный кроп ~4:5.
- Использовать `<picture>` с `<source media="...">` ИЛИ JS-подстановку по ширине.
- `object-fit: cover` на контейнере — чтобы кадр не искажался.
- **Если файла нет** — показывать нейтральный заглушечный блок (тёмный градиент палитры + код сцены мелким текстом), НЕ битую иконку. Приложение должно работать и без картинок (для отладки текста до генерации визуала).
- Ветки C/R/X Акта IV на старте используют `placeholder-{river}.jpg` для всех 3 сцен.

Плавное появление картинки (fade-in) при смене сцены.

## 6. СЛУЖЕБНЫЙ СЛОЙ (режим отладки)

Переключатель вверху (по умолчанию ВКЛ на пилот-версии, чтобы автор отлаживал):

- Под каждым выбором — его вектор (любовь▼+3), что закрывает, «природа».
- Панель под выборами: тяги всех русел, текущий лидер, достижимые финалы.
- В развязке акта и финале — служебная строка: тяги, закрытые русла, путь.
- Класс `body.debug` показывает/скрывает весь служебный слой через CSS.

В «чистом» режиме (галочка снята) — служебного не видно, как у конечного игрока.

## 7. СИСТЕМА ЗАМЕТОК ОТЛАДЧИКА

Под каждой сценой — поле `<textarea>` «Заметка отладчика к этой сцене» + кнопка «Сохранить заметку». Заметки хранятся в памяти (объект `comments[sceneCode] = text`). **НЕ использовать localStorage** (может быть недоступен). Кнопка «Выгрузить все комментарии» собирает заметки в один текст по порядку сцен + путь прохождения, показывает в `<textarea>` для копирования и пытается `execCommand('copy')` / `navigator.clipboard`.

## 9. ДЕПЛОЙ (GitHub Pages)

1. Все файлы — в корень репозитория.
2. Обязателен пустой файл `.nojekyll` в корне (иначе Pages может не отдать папки `js/`/`css/`).
3. Settings → Pages → Source: Deploy from branch → main / root.
4. Приватный репозиторий на платном тарифе: Pages-сайт по умолчанию требует аутентификации GitHub. Для доступа тестировщиков без аккаунта — в Settings → Pages выставить visibility сайта Public (при этом исходник остаётся приватным).
5. Кеш Pages агрессивный: при замене картинок/данных — версионировать имя файла (`scenario_data.json?v=2`) или коммитить с изменением имени, чтобы обойти кеш.

## 10. ЧТО ВАЖНО НЕ СЛОМАТЬ

- Данные отдельно от кода (JSON), чтобы автор правил текст без программиста.
- Числа механики в константах — калибруются после пилота.
- Приложение работает без картинок (заглушки), чтобы отлаживать текст сразу.
- Никакого рантайм-ИИ, никакого серверного кода — чистая статика.
- Никакого localStorage/sessionStorage.
- Акт IV: F идёт по ветке L. Ни один путь не должен оставить игрока без финала (если все русла живы — берётся лидер; проверено симуляцией, тупиков нет).
