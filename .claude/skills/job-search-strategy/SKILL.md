# Стратегия поиска работы

Методика — `career/methodology/06-job-search.md`, профиль —
`career/profile/profile.md` (блоки «Цель» и «Позиционирование»).
Рабочие файлы: `career/search/strategy.md` (план) и
`career/search/applications.md` (лог откликов).

## Режим 1: старт поиска

1. Из профиля взять целевую роль, рынок, ограничения. Если позиционирование
   не сформулировано — сначала закрыть это (см. `01-pipeline.md`, этап 2).
2. Выбрать каналы под рынок (RU: hh + Habr Career + телеграм + рефералы;
   intl: LinkedIn + прямые отклики + борды + рефералы) с целевым сплитом усилий
   из методики.
3. Составить недельный план: N качественных откликов (по умолчанию 10–20),
   нетворкинг-действия, гигиена (поднятие резюме на hh, follow-up).
   Калибровать N под занятость пользователя — спросить.
4. Создать лог откликов из шаблона ниже, если его нет.
5. Провести аудит находимости по чек-листу из `08-recruiter-lens.md`
   (LinkedIn/hh под поисковые запросы рекрутеров, GitHub, поиск себя,
   сообщества) — результат и задачи по исправлению записать в strategy.md.

## Режим 2: еженедельный разбор

1. Прочитать лог откликов, посчитать воронку за неделю и накопительно:
   отклики → просмотры → скрининги → тех.этапы → финалы → офферы.
2. Сравнить конверсии с порогами из методики (таблица «Диагностика»);
   назвать самое узкое место.
3. Предложить ОДНО изменение на следующую неделю (правило «одна переменная
   за раз») и записать его в strategy.md как эксперимент с ожидаемым эффектом.
4. Гигиена: отклики старше 7–10 дней без ответа — список для follow-up;
   ghosted старше 3 недель — закрыть.
5. Обновить strategy.md: итоги недели, активный эксперимент, план.

## Шаблон лога откликов (`career/search/applications.md`)

```markdown
| Дата | Компания | Роль | Ссылка | Канал | Резюме (версия) | Письмо | Статус | След. шаг / дата |
|---|---|---|---|---|---|---|---|---|
```

Статусы: applied → viewed → screening → tech → final → offer / rejected / ghosted.
Входящие от рекрутеров логировать той же таблицей с каналом `inbound` —
их конверсия сравнивается с исходящими откликами (см. `08-recruiter-lens.md`).

## Правила

- Не позволять веерную рассылку: 100 неадаптированных откликов хуже 15 точных —
  показать это пользователю на его же конверсиях.
- Отказы и фидбек — фиксировать в лог; 3+ отказа с одинаковой причиной =
  системная правка (резюме, уровень ролей, подготовка).
- Стратегия — живой документ: каждый разбор дописывает его, а не переписывает.
